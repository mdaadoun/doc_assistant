## 🎯 Objective
Implement enhanced citation validation and verification logic in `CitationValidator` (`src/generation/citations.py`) to audit generated inline document citations against retrieved context blocks, enforce zero-tolerance citation accuracy ($citation\_accuracy = 1.00$) via strict-mode error gating (`strict=True`), provide targeted document presence checks (`verify_document_presence`), and enable non-destructive citation tag filtering (`filter_invalid_citations`).

---

## 💡 Architectural Choices

### 1. Strict-Mode Grounding Validation Enforcement (`strict=True`)
- **Context:** Hallucinated document references undermine trust in corporate RAG platforms. Zero-tolerance targets ($citation\_accuracy = 1.00$) require explicit exception boundaries when validation fails.
- **Decision:** Updated `CitationValidator.validate` with a `strict: bool = False` flag. When active and invalid citations are detected, it logs warning telemetry and raises `GenerationError` (`code="CITATION_VALIDATION_ERROR"`).
- **Rationale:** Prevents ungrounded or hallucinated answers from silently propagating to downstream API clients or end users.

### 2. Direct Document & Page Presence Checking (`verify_document_presence`)
- **Context:** Certain retrieval workflows need to verify whether a specific document and page exist within candidate context sets without parsing full completion strings.
- **Decision:** Implemented `verify_document_presence(file_name, page_number, contexts)` using case-insensitive document name matching and 1-indexed page matching.
- **Rationale:** Delivers fast $O(N)$ targeted lookups over candidate context lists ($N \le 50$) with minimal execution overhead.

### 3. Non-Destructive Tag Filtering (`filter_invalid_citations`)
- **Context:** When generative completions contain a mix of valid and ungrounded citation tags, downstream consumers may prefer sanitizing the text over rejecting the complete completion payload.
- **Decision:** Implemented `filter_invalid_citations(text, contexts)` which strips invalid `[Doc: ... | Page: ...]` tags via regular expression substitution and returns `(cleaned_text, valid_citations)`.
- **Rationale:** Provides post-processing fallback mechanisms to sanitize answer completions while extracting verified source citations.

---

## ⚖️ Trade-offs & Mitigations

| Architectural Choice | Trade-off | Mitigation Strategy |
| :--- | :--- | :--- |
| **Strict-Mode Exception Raising** | Aborts answer generation when any inline citation tag is ungrounded. | Strict mode can be toggled on/off (`strict=False`) for permissive fallback pipelines. |
| **Completion Text Tag Filtering** | Modifies the raw text generated by the LLM post-hoc. | Regex substitution preserves valid inline tags and removes only unmatched hallucinated tags. |
| **Targeted Document Presence Lookup** | Evaluates document-page tuples independently of completion text parsing. | Complements regular expression text parsing by providing direct boolean lookup utilities. |

## 🛠️ Implementation & Code

### Key Flows
```text
CitationValidator.validate(text_or_citations, contexts, strict=False)
  ├── 1. Parse raw tags via CitationExtractor.extract_raw(text) OR map Citation list to RawCitation instances
  ├── 2. Extract context metadata via CitationExtractor._extract_context_meta(ctx)
  ├── 3. Match raw citations against context metadata (case-insensitive filename, exact page_number)
  │        ├── If matched -> Construct valid Citation -> Append to valid_citations
  │        └── If unmatched -> Append to invalid_citations
  ├── 4. Calculate citation_accuracy = len(valid) / total -> Set is_valid = (len(invalid) == 0)
  └── 5. If strict and not is_valid -> Log structlog warning -> Raise GenerationError(code="CITATION_VALIDATION_ERROR")
```
